# Restored NCDC V1.3.3 batch workflow

`cure-ngs batch-vcf-to-maf` is the portable, containerized successor to
`NCDC_batch_vcf2maf_V.1.3.3`. It retains the operational behavior needed for
heterogeneous institutional VCF collections while removing workstation-specific
paths from the program.

## Feature mapping

| NCDC V1.3.3 behavior | Unified implementation |
| --- | --- |
| Recursively find VCF-family inputs | `.vcf`, `.g.vcf`, `.vcf.gz`, `.g.vcf.gz`, `.vcf.vep`, bzip2/xz, and named VCF archives |
| Safe handling of spaces and parentheses | Stable sanitized work/output names; collisions are rejected before work starts |
| Windows CRLF conversion | Every input is staged as UTF-8 with LF endings |
| GINS missing ID/QUAL repair | Legacy `#CHROM POS REF ALT ...` records are converted to standard VCF columns |
| Missing FORMAT/sample header repair | FORMAT and the filename-derived sample tag are added when data columns prove they are missing |
| Missing caller tag declarations | Used but undeclared INFO, FORMAT, and FILTER IDs receive conservative auditable definitions |
| gVCF conversion | Multiallelic records are split and non-small-variant alleles such as `<NON_REF>` are removed with bcftools |
| SNV/indel-only scope | Breakends, symbolic SVs, and non-ACGTN vendor ALT encodings are excluded before reference normalization |
| GRCh37/GRCh38 detection | Header reference, assembly attributes, and chromosome 1 lengths are inspected; an explicit override is available |
| GRCh38 to GRCh37 liftover | Ordered chain fallback with chain-specific contig style and target FASTA selection |
| Three GRCh37 FASTA fallbacks | Any ordered number of FASTA candidates can be declared in the reference config |
| Empty VCF handling | A deterministic header-only MAF and manifest are created without calling VEP |
| Filename-derived eight-character barcode | `--sample-tag-length 8` is the default and can be changed |
| Tumor/normal detection | A normal-like sample name is detected from the first two VCF samples; the decision is written to the manifest |
| Parallel processing | `--jobs N` runs independent per-input work directories concurrently |
| TSV status log | `vcf2maf_batch_log.tsv`, a JSON summary, and one hash-bearing manifest per successful output are written |

Two legacy behaviors are available but safety-hardened:

- Unknown input assembly falls back to GRCh37 only when
  `"unknown_assembly": "GRCh37"` is present in the config. The fallback is
  explicit in the per-file attempt log. Set it to `null` for strict detection.
- Treating an all-rejected liftover as an empty result requires
  `"allow_all_rejected_empty": true`. The supplied example uses `false`, so an
  all-rejected conversion fails visibly instead of becoming a false negative.

## Why reference files are not in the image

Human FASTAs and VEP caches are several gigabytes and differ across
institutions. Baking them into the image would make distribution slow and would
couple software releases to local data. CURE-NGS therefore separates:

```text
container image                 host/NAS reference bundle
-----------------------------   ----------------------------------
Python CLI                      GRCh37 FASTA candidates
bcftools and samtools           FASTA .fai and Picard .dict files
VEP 116.1 and vcf2maf           VEP 116 GRCh37 cache
Picard 3.1.1                    GRCh38-to-GRCh37 chain candidates
```

The host directory is mounted read-only at `/references`. No reference file is
copied into the container and no host-specific path is present in source code.

## Reference configuration

The user selects the real reference directory; CURE-NGS never searches the
whole workstation. Create a config in a small writable directory while keeping
the large reference tree wherever the institution already stores it:

```bash
REFERENCE_DIR=/path/to/your/reference-store
mkdir -p config
docker run --rm --user "$(id -u):$(id -g)" \
  --volume "$PWD/config:/config" \
  ghcr.io/ncdcbioinformatics/cure-ngs-harmonizer:0.2.1 init-reference-config \
  /config/reference-config.json \
  --reference-root /references --cache-version 116
```

The left side of the later Docker mount selects `REFERENCE_DIR`; `/references`
is its stable name inside the container. Edit the generated relative paths if
the institution does not use the standard layout. The repository also contains
`references/reference-config.example.json` for manual copying.

All paths in the JSON file are relative to `reference_root`. With the default
layout, the file itself is under the mounted reference root:

```text
references/
|-- reference-config.json
|-- grch37/
|   |-- hg19.fa
|   |-- hg19.fa.fai
|   |-- hg19.dict
|   |-- Homo_sapiens_assembly19.fasta
|   |-- Homo_sapiens_assembly19.fasta.fai
|   |-- Homo_sapiens_assembly19.dict
|   |-- Homo_sapiens.GRCh37.dna.toplevel.fa
|   |-- Homo_sapiens.GRCh37.dna.toplevel.fa.fai
|   `-- Homo_sapiens.GRCh37.dna.toplevel.dict
|-- liftover/
|   |-- hg38ToHg19.over.chain.gz
|   `-- GRCh38_to_GRCh37.chain.gz
`-- vep/
    `-- homo_sapiens/
        `-- 116_GRCh37/
```

The order of `fasta_candidates` and `chains` is the retry order. A chain can
name its matching target FASTA with `target_reference_label`; this avoids the
common error of combining a UCSC `chr1` chain with a numeric-contig target
reference. Remove candidates that are not installed. `doctor-bundle` requires
every resource that remains configured.

### Discovery versus automatic selection

CURE-NGS deliberately does not crawl an entire workstation or NAS looking for
files whose names resemble a genome. That would be ambiguous and could silently
select a wrong build. The config and `--reference-root` define the finite,
auditable search space. Within that space the batch workflow operates
automatically: it detects each input VCF assembly, bypasses liftover for native
GRCh37, chooses the configured GRCh38-to-GRCh37 profile when required, and
tries chain and FASTA candidates in declared order.

`doctor-bundle` validates both path resolution and resource identity. It checks:

- each FASTA and `.fai`, including chromosome 1 length for GRCh37 or GRCh38;
- observed UCSC (`chr1`) or numeric (`1`) contig style against the config;
- each Picard `.dict`, including its chromosome 1 length;
- chain direction from chromosome 1 source/target lengths;
- chain source style and compatibility with the linked target FASTA;
- VEP cache directory version, `homo_sapiens` species, assembly metadata, and
  chromosome 1 cache payload;
- installed VEP major release compatibility with the configured cache version;
- optional configured SHA-256 digests.

An institution can keep the config outside its large shared resource tree and
override only the root:

```bash
--volume /institution/reference-store:/references:ro \
--volume "$PWD/config:/config:ro" \
--reference-config /config/reference-config.json \
--reference-root /references
```

Optional `sha256` fields may be added to individual FASTA and chain objects.
`doctor-bundle` verifies those checksums once; per-sample runs then record the
configured digest without repeatedly hashing a multi-gigabyte FASTA.

`"output_contig_style": "numeric"` preserves the database-facing V1.3.3
convention (`1`, `X`, `MT`) even when a UCSC `chr`-prefixed FASTA is selected.
Set it to `"ucsc"` only when downstream rows explicitly require `chr1`-style
chromosomes.

## Preflight and batch run

```bash
docker run --rm \
  --volume "$REFERENCE_DIR:/references:ro" \
  --volume "$PWD/config:/config:ro" \
  ghcr.io/ncdcbioinformatics/cure-ngs-harmonizer:0.2.1 doctor-bundle \
  --reference-config /config/reference-config.json \
  --reference-root /references \
  | tee reference-bundle.preflight.json
```

Only run the batch after the report says `"status": "READY"`:

```bash
mkdir -p output
chmod 0777 output

docker run --rm --read-only --tmpfs /tmp:size=2g,mode=1777 \
  --security-opt no-new-privileges:true \
  --volume "$PWD/input:/data/input:ro" \
  --volume "$PWD/output:/data/output" \
  --volume "$REFERENCE_DIR:/references:ro" \
  --volume "$PWD/config:/config:ro" \
  ghcr.io/ncdcbioinformatics/cure-ngs-harmonizer:0.2.1 batch-vcf-to-maf \
  /data/input /data/output \
  --reference-config /config/reference-config.json \
  --reference-root /references \
  --jobs 4 --forks 1
```

The target assembly comes from the config and defaults to GRCh37. For an input
with no reliable assembly metadata, either retain the audited GRCh37 fallback
in the config or declare the batch explicitly with
`--source-assembly GRCh37`.

## Outputs and failure behavior

Each input receives a separate work directory, MAF, and manifest. The batch
returns exit code 2 if any item fails, but it continues processing independent
items so that one malformed institutional file does not discard successful
results. Existing MAFs are protected unless `--overwrite` is supplied.

Retain these files together:

- `*.maf`
- `*.maf.manifest.json`
- `vcf2maf_batch_log.tsv`
- `vcf2maf_batch_summary.json`

The manifest identifies the selected FASTA and chain, every failed fallback
attempt, assembly decision, sample assignment, exact VCF/config hashes,
vcf2maf hash, and VEP cache version.

Confirm the automatic decision for every input after the run:

```bash
jq '.items[] | {
  input_path, source_assembly, target_assembly,
  chosen_chain, chosen_reference, status
}' output/vcf2maf_batch_summary.json

jq '.parameters | {
  source_assembly, target_assembly,
  chosen_chain, chosen_reference, attempts
}' output/sample.maf.manifest.json
```

The first command audits the whole batch. The second shows the exact selected
files and every fallback attempt for one sample.
